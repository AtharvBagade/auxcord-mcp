# Single Canonical Launcher in main.py, Streamable-HTTP Only

`main.py` remains the one canonical launcher (`--transport {stdio,http}`, default `stdio`), rather than moving CLI/transport logic into `src/mcp_server.py` to match the PRD's literal `python -m src.mcp_server` wording: `main.py` already owned the packaged `spotify-mcp` script entrypoint and CLI argument parsing, and `src/mcp_server.py` is kept focused on FastMCP server construction and tool/resource registration. Duplicating launcher logic into both files would just create two things to keep in sync for no benefit. For `--transport http`, only modern streamable-HTTP (FastMCP's `transport="http"`) is supported, not the legacy `sse` transport value — current MCP clients (Claude Desktop, Cursor, Antigravity) all target streamable-HTTP, and the MCP spec is phasing legacy SSE out. `host`/`port` are read from `SpotifySettings` (`mcp_host`/`mcp_port`), overridable via `--host`/`--port`, consistent with how `spotify_redirect_uri` and other deployment-specific values are already env-configurable.
